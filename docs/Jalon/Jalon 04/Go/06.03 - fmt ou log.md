# Go — Afficher des messages avec `fmt` et `log`

## Objectif

Comprendre la différence entre :

```go
fmt.Println("Serveur lancé")
```

et :

```go
log.Println("Serveur lancé")
```

Les deux fonctions affichent un message dans le terminal, mais elles ne répondent pas exactement au même besoin.

---

## 1. `fmt.Println`

Le package `fmt` sert principalement à **formater et afficher des valeurs**.

```go
fmt.Println("Serveur lancé sur http://localhost:8080")
```

Affichage obtenu :

```text
Serveur lancé sur http://localhost:8080
```

Par défaut, `fmt.Println` écrit dans la sortie standard du programme, appelée `stdout`.

### Utilisations courantes

`fmt.Println` est pratique pour :

- afficher un résultat destiné à l’utilisateur ;
    
- tester rapidement une valeur pendant le développement ;
    
- écrire un petit programme en ligne de commande ;
    
- comprendre le déroulement d’un programme.
    

Exemple :

```go
name := "Alice"

fmt.Println("Nom du membre :", name)
```

---

## 2. `log.Println`

Le package `log` sert à produire des **journaux d’exécution**, aussi appelés logs.

```go
log.Println("Serveur lancé sur http://localhost:8080")
```

Affichage possible :

```text
2026/08/06 00:11:00 Serveur lancé sur http://localhost:8080
```

Le logger standard ajoute automatiquement la date et l’heure au message. Par défaut, ses messages sont écrits dans la sortie d’erreur standard, appelée `stderr`.

Ces informations permettent de savoir :

- quand un événement a eu lieu ;
    
- dans quel ordre les événements se sont produits ;
    
- à quel moment une erreur est apparue.
    

---

## 3. Différence principale

|Fonction|Rôle principal|
|---|---|
|`fmt.Println`|Afficher une information ou une valeur|
|`log.Println`|Enregistrer un événement survenu pendant l’exécution|

On peut résumer ainsi :

```text
fmt = affichage
log = journal de l’application
```

---

## 4. Pourquoi utiliser `log` dans un serveur web ?

Un serveur peut fonctionner longtemps et traiter de nombreuses requêtes.

Il est donc utile de conserver des informations comme :

```text
Le serveur a démarré.
La configuration a été chargée.
La connexion à la base de données a échoué.
Une requête a provoqué une erreur.
```

Par exemple :

```go
log.Println("configuration chargée")
log.Println("serveur lancé sur http://localhost:8080")
```

En cas de problème, les logs permettent de reconstruire ce qui s’est passé.

---

## 5. `log.Println` et `log.Printf`

### `log.Println`

`log.Println` affiche les valeurs les unes après les autres et ajoute une fin de ligne.

```go
port := 8080

log.Println("serveur lancé sur le port", port)
```

Résultat :

```text
2026/08/06 00:11:00 serveur lancé sur le port 8080
```

### `log.Printf`

`log.Printf` permet d’utiliser des verbes de formatage comme `%s`, `%d` ou `%v`.

```go
port := 8080

log.Printf("serveur lancé sur le port %d", port)
```

Résultat :

```text
2026/08/06 00:11:00 serveur lancé sur le port 8080
```

Attention : les verbes de formatage ne sont interprétés que par les fonctions terminant par `f`, comme `Printf`.

Incorrect :

```go
log.Println("port : %d", port)
```

Correct :

```go
log.Printf("port : %d", port)
```

---

## 6. `log.Fatal` et `log.Fatalf`

Les fonctions `Fatal` affichent un message puis arrêtent immédiatement le programme avec un code d’erreur. Elles appellent `os.Exit(1)`.

### Sans formatage

```go
log.Fatal("impossible de démarrer le serveur")
```

### Avec formatage

```go
log.Fatalf("impossible de charger la configuration : %v", err)
```

Cela revient approximativement à faire :

```go
log.Printf("impossible de charger la configuration : %v", err)
os.Exit(1)
```

### Conséquence importante

Les fonctions placées dans un `defer` ne sont pas exécutées après un `log.Fatal`, puisque le programme est interrompu par `os.Exit`.

Pour cette raison, `log.Fatal` est principalement utilisé dans `main`, lorsque l’application ne peut pas continuer.

Exemple :

```go
func main() {
	cfg, err := config.Load()
	if err != nil {
		log.Fatalf("impossible de charger la configuration : %v", err)
	}
}
```

En revanche, une fonction interne doit généralement retourner l’erreur :

```go
func Load() (*Config, error) {
	// ...
	return nil, err
}
```

Elle ne doit pas décider elle-même d’arrêter toute l’application.

---

## 7. `log.Panic`

Il existe également :

```go
log.Panic("erreur inattendue")
```

Cette fonction :

1. écrit le message dans les logs ;
    
2. déclenche un `panic`.
    

Contrairement à `log.Fatal`, les fonctions différées avec `defer` peuvent alors être exécutées pendant la remontée du `panic`.

Dans une application classique, `log.Panic` doit rester rare.

## 8. Application à Club Manager

Dans `main`, utiliser `log` est cohérent pour annoncer les événements liés au fonctionnement du serveur :

```go
func main() {
	cfg, err := config.Load("config.json")
	if err != nil {
		log.Fatalf("impossible de charger la configuration : %v", err)
	}

	_ = cfg

	mux := router.New()

	log.Println("serveur lancé sur http://localhost:8080")

	if err := http.ListenAndServe(":8080", mux); err != nil {
		log.Fatal(err)
	}
}
```

Ici :

- le chargement impossible de la configuration empêche le démarrage ;
    
- l’erreur est donc fatale ;
    
- le démarrage du serveur est un événement intéressant à journaliser ;
    
- une erreur retournée par `ListenAndServe` doit également être enregistrée.
    

---

## 9. Quand conserver `fmt` ?

Le remplacement de `fmt` par `log` ne signifie pas que `fmt` devient inutile.

Le package `fmt` reste utilisé pour :

### Écrire dans une réponse HTTP

```go
fmt.Fprintln(w, "Bienvenue sur Club Manager")
```

Ici, le texte est envoyé au navigateur par l’intermédiaire du `ResponseWriter`.

### Construire une chaîne

```go
message := fmt.Sprintf("Membre numéro %d", memberID)
```

### Construire une erreur

```go
return fmt.Errorf("chargement de la configuration : %w", err)
```

### Afficher une valeur dans un programme en ligne de commande

```go
fmt.Println("Résultat :", result)
```

---

## 10. Règle pratique

Dans Club Manager :

```text
Message destiné au navigateur → fmt.Fprintln ou template
Message destiné au journal du serveur → log.Println ou log.Printf
Erreur empêchant main de continuer → log.Fatal ou log.Fatalf
Erreur dans une fonction interne → return err
```

---

## Comprendre et retenir

`fmt` sert à afficher ou à construire du texte.

`log` sert à raconter ce qui se passe pendant l’exécution de l’application.

Dans un serveur web, les logs sont particulièrement utiles parce que l’application peut fonctionner longtemps et rencontrer des événements que l’utilisateur ne voit pas directement.

La différence essentielle est donc la destination du message :

```text
Utilisateur ou navigateur → fmt
Développeur ou administrateur du serveur → log
```

Pour commencer, le package standard `log` est largement suffisant pour Club Manager. Il sera toujours possible d’étudier plus tard les logs structurés avec `log/slog`.
