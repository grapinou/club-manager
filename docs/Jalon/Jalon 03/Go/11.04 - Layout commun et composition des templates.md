# Layout commun et composition des templates

## Objectif

Lorsque plusieurs pages HTML appartiennent à une même application, elles partagent généralement une structure commune :

- la déclaration `DOCTYPE` ;
    
- les balises `<html>`, `<head>` et `<body>` ;
    
- le titre de l’onglet ;
    
- l’en-tête du site ;
    
- la navigation ;
    
- le pied de page.
    

Seul le contenu principal change d’une page à l’autre.

Dans Club Manager, nous voulons donc séparer :

```text
Structure commune du site
          +
Contenu propre à chaque page
```

Cette organisation permet d’éviter de répéter toute la structure HTML dans chaque fichier.

---

## Avant le layout commun

Au départ, le template de la page d’accueil contenait tout le document HTML :

```html
<!DOCTYPE html>

<html lang="fr">

<head>
    <meta charset="UTF-8">
    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >

    <title>{{ .Title }}</title>
</head>

<body>
    <h1>{{ .Heading }}</h1>

    <p>
        {{ .Description }}
    </p>
</body>

</html>
```

Cette solution fonctionne correctement pour une seule page.

Cependant, si nous créons les pages `/club`, `/contact` et `/rules` de la même manière, nous allons répéter :

```html
<!DOCTYPE html>
<html>
<head>
<body>
```

Nous répéterons également plus tard :

- l’en-tête ;
    
- la navigation ;
    
- le pied de page ;
    
- les fichiers CSS ;
    
- les informations générales du site.
    

---

## Nouvelle organisation

Les templates sont maintenant répartis dans deux dossiers :

```text
internal/
└── views/
    ├── 001_home.go
    │
    └── templates/
        ├── layouts/
        │   └── base.html
        │
        └── pages/
            └── 001_home.html
```

Chaque partie possède une responsabilité différente.

```text
templates/layouts/
└── structures communes à plusieurs pages

templates/pages/
└── contenu propre à chaque page
```

---

# 1. Le layout commun

Le fichier suivant contient la structure générale du site :

```text
templates/layouts/base.html
```

Son contenu est :

```html
{{ define "base" }}

<!DOCTYPE html>

<html lang="fr">

<head>
    <meta charset="UTF-8">

    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >

    <title>{{ .Title }}</title>
</head>

<body>

    <header>
        <p>Club Manager</p>
    </header>

    <main>
        {{ template "content" . }}
    </main>

    <footer>
        <p>Club Manager</p>
    </footer>

</body>

</html>

{{ end }}
```

---

## Définir le template `base`

La première instruction est :

```html
{{ define "base" }}
```

Elle crée un template nommé :

```text
base
```

Tout ce qui se trouve entre :

```html
{{ define "base" }}
```

et :

```html
{{ end }}
```

appartient à ce template.

Nous pouvons rapprocher cela de la déclaration d’une fonction en Go :

```go
func base() {
	// Structure commune
}
```

Le template possède un nom qui permettra de l’exécuter plus tard :

```text
base
```

---

## Prévoir un emplacement pour le contenu

Dans le layout, la balise `<main>` contient :

```html
<main>
    {{ template "content" . }}
</main>
```

Cette instruction signifie :

> Exécuter à cet endroit le template nommé `content`.

Le layout ne connaît pas encore le contenu exact de la page.

Il sait uniquement qu’un template appelé `content` devra être inséré dans `<main>`.

```text
base
├── header
├── main
│   └── emplacement réservé à content
└── footer
```

---

## Rôle du point

Dans cette instruction :

```html
{{ template "content" . }}
```

le point représente les données actuelles.

Pour la page d’accueil, ces données sont contenues dans :

```go
type HomeData struct {
	Title       string
	Heading     string
	Description string
}
```

Le point permet de transmettre ces mêmes données au template `content`.

```text
HomeData
   ↓
base
   ↓
content
```

Le layout peut utiliser :

```html
{{ .Title }}
```

et le contenu de la page peut utiliser :

```html
{{ .Heading }}
{{ .Description }}
```

Les deux templates reçoivent la même structure de données.

---

# 2. Le contenu de la page d’accueil

Le fichier suivant contient uniquement le contenu propre à l’accueil :

```text
templates/pages/001_home.html
```

Son contenu est :

```html
{{ define "content" }}

<h1>{{ .Heading }}</h1>

<p>
    {{ .Description }}
</p>

{{ end }}
```

---

## Définir le template `content`

Cette instruction :

```html
{{ define "content" }}
```

crée un template nommé :

```text
content
```

Le layout demande justement l’exécution de ce template :

```html
{{ template "content" . }}
```

Les deux fichiers sont donc liés par le nom `content`.

```text
base.html
└── appelle "content"

001_home.html
└── définit "content"
```

Le nom doit être strictement identique dans les deux fichiers.

```html
{{ template "content" . }}
```

doit correspondre à :

```html
{{ define "content" }}
```

---

## Une page ne contient plus tout le document

Le fichier `001_home.html` ne possède plus :

```html
<!DOCTYPE html>
<html>
<head>
<body>
```

Il contient seulement ce qui change pour cette page :

```html
<h1>{{ .Heading }}</h1>

<p>
    {{ .Description }}
</p>
```

La répartition devient :

```text
base.html
├── document HTML
├── head
├── header
├── main
└── footer

001_home.html
├── titre principal
└── description
```

---

# 3. Intégrer les fichiers avec `go:embed`

Le programme Go doit avoir accès aux deux fichiers :

```text
base.html
001_home.html
```

Ils sont intégrés dans le programme avec :

```go
//go:embed templates/layouts/base.html
//go:embed templates/pages/001_home.html
var homeFiles embed.FS
```

Il est également possible d’écrire les deux chemins sur une seule ligne :

```go
//go:embed templates/layouts/base.html templates/pages/001_home.html
var homeFiles embed.FS
```

La variable `homeFiles` contient maintenant les deux fichiers.

```text
homeFiles
├── templates/layouts/base.html
└── templates/pages/001_home.html
```

---

## Attention à la syntaxe de `go:embed`

La directive doit être écrite exactement ainsi :

```go
//go:embed
```

Il ne faut pas ajouter d’espace :

```go
// go:embed
```

La seconde version est un commentaire ordinaire et n’est pas reconnue comme une directive par Go.

---

# 4. Analyser les deux templates

Les fichiers intégrés doivent ensuite être analysés ensemble :

```go
var homeTemplate = template.Must(
	template.ParseFS(
		homeFiles,
		"templates/layouts/base.html",
		"templates/pages/001_home.html",
	),
)
```

`ParseFS` reçoit :

1. le système de fichiers intégré ;
    
2. le chemin du layout ;
    
3. le chemin du contenu de la page.
    

```text
homeFiles
   ↓
ParseFS
   ├── base.html
   └── 001_home.html
   ↓
homeTemplate
```

Les deux fichiers appartiennent alors au même ensemble de templates.

Cela permet au template `base` d’appeler le template `content`.

Si les fichiers étaient analysés séparément, ils ne pourraient pas se retrouver aussi simplement par leur nom.

---

# 5. Exécuter le layout

La fonction `RenderHome` devient :

```go
func RenderHome(w io.Writer, data HomeData) error {
	return homeTemplate.ExecuteTemplate(
		w,
		"base",
		data,
	)
}
```

Nous demandons à Go d’exécuter le template nommé :

```text
base
```

Ce nom correspond à :

```html
{{ define "base" }}
```

---

## Nom du fichier et nom du template

Il faut distinguer deux éléments.

### Chemin du fichier

```text
templates/layouts/base.html
```

Ce chemin est utilisé par :

```go
template.ParseFS(
	homeFiles,
	"templates/layouts/base.html",
)
```

Il permet de retrouver le fichier dans le système de fichiers intégré.

### Nom du template

```text
base
```

Ce nom est créé dans le fichier avec :

```html
{{ define "base" }}
```

Il est utilisé lors de l’exécution :

```go
ExecuteTemplate(
	w,
	"base",
	data,
)
```

Le nom du fichier et le nom défini dans le template ne sont donc pas nécessairement identiques.

```text
Chemin du fichier
templates/layouts/base.html

Nom du template
base
```

---

## L’erreur rencontrée

L’appel suivant est incorrect dans notre cas :

```go
homeTemplate.ExecuteTemplate(
	w,
	"base.html",
	data,
)
```

Il demande à Go d’exécuter un template nommé :

```text
base.html
```

Or notre fichier définit :

```html
{{ define "base" }}
```

Le template réellement disponible s’appelle donc :

```text
base
```

La correction est :

```go
homeTemplate.ExecuteTemplate(
	w,
	"base",
	data,
)
```

---

# 6. Parcours complet du rendu

Lorsque le handler appelle :

```go
views.RenderHome(w, data)
```

le parcours est le suivant :

```text
HomeHandler
    ↓
crée HomeData
    ↓
RenderHome
    ↓
ExecuteTemplate("base", data)
    ↓
exécute le template "base"
    ↓
base rencontre :
{{ template "content" . }}
    ↓
exécute le template "content"
    ↓
utilise Heading et Description
    ↓
termine le layout
    ↓
écrit le HTML dans la réponse
```

---

## Représentation des liens entre les fichiers

```text
internal/handlers/001_home.go
│
│ crée HomeData
│ appelle RenderHome
↓
internal/views/001_home.go
│
│ intègre les deux fichiers avec go:embed
│ les analyse ensemble avec ParseFS
│ exécute le template "base"
↓
templates/layouts/base.html
│
│ définit "base"
│ utilise .Title
│ appelle "content"
↓
templates/pages/001_home.html
│
│ définit "content"
│ utilise .Heading
│ utilise .Description
↓
Réponse HTML
```

---

# 7. Le rôle de chaque fichier

|Fichier|Responsabilité|
|---|---|
|`handlers/001_home.go`|Préparer les données de la page|
|`views/001_home.go`|Intégrer, analyser et exécuter les templates|
|`layouts/base.html`|Définir la structure HTML commune|
|`pages/001_home.html`|Définir le contenu propre à l’accueil|

Chaque fichier possède maintenant une responsabilité identifiable.

---

# 8. Pourquoi cette séparation est utile

## Éviter la répétition

La structure générale du site n’est écrite qu’une seule fois :

```text
base.html
```

Les futures pages pourront réutiliser :

- le même `<head>` ;
    
- le même header ;
    
- la même navigation ;
    
- le même footer.
    

---

## Modifier tout le site depuis un seul fichier

Pour ajouter une navigation commune, nous modifierons uniquement :

```text
templates/layouts/base.html
```

Toutes les pages utilisant ce layout bénéficieront ensuite de la modification.

---

## Garder les pages simples

Chaque fichier de page contient uniquement son contenu particulier.

```text
001_home.html
└── accueil

002_club.html
└── présentation du club

003_contact.html
└── informations de contact
```

---

## Préparer les futures évolutions

Cette architecture permettra plus tard d’ajouter dans le layout :

- Bootstrap ;
    
- une feuille de style ;
    
- une navigation ;
    
- un logo ;
    
- le nom personnalisé du club ;
    
- les liens communs ;
    
- un pied de page configurable.
    

Le contenu particulier de chaque page restera séparé.

---

# 9. Limite actuelle

Pour l’instant, seul le template de la page d’accueil définit :

```html
{{ define "content" }}
```

Le layout est donc techniquement séparé, mais sa réutilisation deviendra réellement visible lorsqu’une deuxième page l’utilisera.

La prochaine étape pourra être :

```text
Créer le contenu de la page /club
        ↓
L’analyser avec base.html
        ↓
Exécuter le même template "base"
```

Nous obtiendrons alors :

```text
base.html
├── contenu de l’accueil
└── contenu de la page du club
```

---

# Comprendre et retenir

Un layout contient la structure commune de plusieurs pages.

```text
Layout
├── head
├── header
├── emplacement du contenu
└── footer
```

Une page contient uniquement son contenu particulier.

```text
Page d’accueil
├── heading
└── description
```

`define` permet de créer un template nommé :

```html
{{ define "base" }}
```

```html
{{ define "content" }}
```

`template` permet d’exécuter un template nommé depuis un autre template :

```html
{{ template "content" . }}
```

`ParseFS` analyse les fichiers ensemble :

```go
template.ParseFS(
	homeFiles,
	"templates/layouts/base.html",
	"templates/pages/001_home.html",
)
```

`ExecuteTemplate` exécute le nom déclaré avec `define` :

```go
ExecuteTemplate(
	w,
	"base",
	data,
)
```

Il faut distinguer :

```text
Chemin du fichier : templates/layouts/base.html
Nom du template : base
```

Le parcours final est :

```text
Handler
   ↓
HomeData
   ↓
RenderHome
   ↓
template "base"
   ↓
template "content"
   ↓
HTML envoyé au navigateur
```
