# Composition d'interfaces

Une interface peut être composée d'autres interfaces.

Exemple :

```go
type Reader interface {
	Read()
}

type Writer interface {
	Write()
}

type ReadWriter interface {
	Reader
	Writer
}
```

`ReadWriter` possède alors toutes les méthodes de :

- Reader
- Writer

En Go :

```text
ReadWriter = Reader + Writer
```

Cela permet de créer des interfaces plus grandes à partir de petites interfaces.

Principe recommandé :

> Préférer plusieurs petites interfaces plutôt qu'une grande interface complexe.


## Exemple simple : une interface composée

Imaginons deux interfaces :

```go
type Reader interface {
	Read()
}

type Writer interface {
	Write()
}
```

On peut créer une nouvelle interface qui regroupe les deux :

```go
type ReadWriter interface {
	Reader
	Writer
}
```

Maintenant, `ReadWriter` signifie :

> "Un objet qui sait lire ET écrire."

Il doit donc obligatoirement posséder :

```
Read()
Write()
```

---

## Visuellement

On peut le représenter ainsi :

```
        Reader
           |
           |
      ReadWriter
           |
           |
        Writer
```

Ou :

```
ReadWriter = Reader + Writer
```

---

## Exemple concret avec Go

La bibliothèque standard utilise énormément ce principe.

Tu connais déjà :

```go
http.ResponseWriter
```

Cette interface représente quelque chose capable d'écrire une réponse HTTP.

Mais derrière, Go utilise aussi des interfaces plus petites :

```go
io.Writer
    |
    |
http.ResponseWriter
```

`io.Writer` dit simplement :

```go
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

Donc :

> "Je sais écrire des octets."

`http.ResponseWriter` ajoute d'autres capacités :

```go
type ResponseWriter interface {
	Header() Header
	Write([]byte)
	WriteHeader(statusCode int)
}
```

Donc :

> "Je sais écrire une réponse HTTP complète."

---

## Pourquoi composer des interfaces ?

Parce qu'une grosse interface devient vite difficile à utiliser.

Imagine :

```go
type ClubManager interface {
	CreateMember()
	DeleteMember()
	UpdateMember()
	FindMember()
	GenerateInvoice()
	SendEmail()
	ExportCSV()
	...
}
```

Elle fait trop de choses.

On préférera :

```go
type MemberReader interface {
	FindMember()
}

type MemberWriter interface {
	CreateMember()
	DeleteMember()
	UpdateMember()
}
```

Puis éventuellement :

```go
type MemberRepository interface {
	MemberReader
	MemberWriter
}
```

Cela donne des composants plus simples.

---

## Une notion importante en Go

On parle souvent du principe :

> **Des interfaces petites et ciblées.**

Go préfère :

```go
type Printer interface {
	Print()
}
```

plutôt que :

```go
type Machine interface {
	Print()
	Scan()
	Fax()
	Copy()
}
```

Car un objet qui sait imprimer n'a pas forcément besoin de savoir scanner ou faxer.
