# Les imports en Go

## Exemple

Dans `main.go` :

```go
import (
	"fmt"
	"net/http"

	"github.com/grapinou/club-manager/internal/handlers"
)
```

Go importe trois packages :

- fmt
- net/http
- handlers

---

# On importe un package, jamais un fichier

On n'écrit jamais :

```go
import "home.go"
```

ni

```go
import "contact.go"
```

On importe toujours le package.

Par exemple :

```go
import "github.com/grapinou/club-manager/internal/handlers"
```

Le compilateur retrouve automatiquement tous les fichiers appartenant au package `handlers`.

---

# Pourquoi cette longue adresse ?

L'import reprend le nom du module déclaré dans le fichier `go.mod`.

Notre fichier `go.mod` contient :

```go
module github.com/grapinou/club-manager
```

C'est le nom officiel de notre module Go.

Tous les imports internes commencent donc par cette adresse.

Par exemple :

```go
import "github.com/grapinou/club-manager/internal/handlers"
```

Le compilateur comprend :

> Dans le module `github.com/grapinou/club-manager`, va chercher le package `internal/handlers`.

---

# Le lien avec GitHub

Le nom du module correspond généralement à l'adresse du dépôt GitHub.

Notre projet est hébergé ici :

github.com/grapinou/club-manager

Le module porte donc le même nom.

Ainsi, si quelqu'un souhaite utiliser notre projet, Go saura où le trouver.

Même lorsque l'on travaille en local, Go utilise le nom du module pour résoudre les imports.

---

# Comment Go retrouve le package ?

Lors de la compilation :

1. Go lit le fichier `go.mod`.
2. Il connaît le nom du module.
3. Il recherche le package demandé à l'intérieur du projet.
4. Il compile tous les fichiers de ce package.

---

# Exemple

Arborescence :

club-manager/
│
├── go.mod
│
└── internal/
    └── handlers/
        ├── home.go
        ├── club.go
        └── contact.go

`go.mod`

```go
module github.com/grapinou/club-manager
```

Import :

```go
import "github.com/grapinou/club-manager/internal/handlers"
```

Go sait alors qu'il doit compiler le package `handlers`.

---

# À retenir

- On importe toujours un package.
- L'import commence par le nom du module déclaré dans `go.mod`.
- Le nom du module correspond généralement au dépôt GitHub.
- Go utilise `go.mod` pour retrouver les packages du projet.
- Tous les fichiers d'un package sont compilés ensemble.


Remarque : 

Le chemin :

```
import "github.com/grapinou/club-manager/internal/handlers"
```

**n'est pas une URL que Go télécharge systématiquement sur Internet**.

Quand tu travailles dans ton projet, Go lit d'abord ton `go.mod`, voit que le module courant est `github.com/grapinou/club-manager` et comprend que cet import désigne un package **local** situé dans ton projet :

```
club-manager/
└── internal/
    └── handlers/
```

L'adresse ressemble à une URL GitHub, mais elle joue surtout le rôle d'un **identifiant unique du module**. Si un autre développeur clone ton dépôt, il obtiendra le même nom de module, les mêmes imports et le projet compilera sans avoir à modifier les chemins. C'est une idée très élégante de Go : utiliser le nom du module comme référence unique, que le code soit compilé localement ou récupéré depuis un dépôt distant. C'est ce qui rend le système d'import à la fois simple et très robuste.
