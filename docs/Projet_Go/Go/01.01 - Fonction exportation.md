# Les fonctions exportées en Go

## Principe

En Go, la visibilité d'une fonction dépend uniquement de la première lettre de son nom.

Il n'existe pas de mots-clés comme :

- public
- private
- protected

La convention est très simple :

- Majuscule → fonction exportée.
- Minuscule → fonction non exportée.

---

# Fonction non exportée

Exemple :

```go
func homeHandler(w http.ResponseWriter, r *http.Request) {

}
```

Cette fonction ne peut être utilisée que par les fichiers appartenant au même package.

Dans notre cas :

```text
internal/
└── handlers/
```

Tous les fichiers du package `handlers` peuvent appeler :

```go
homeHandler()
```

En revanche, un autre package ne pourra pas y accéder.

---

# Fonction exportée

Exemple :

```go
func HomeHandler(w http.ResponseWriter, r *http.Request) {

}
```

La fonction devient exportée.

Elle peut être utilisée depuis un autre package.

Par exemple :

```go
package main

import (
    "github.com/grapinou/club-manager/internal/handlers"
)

func main() {

    handlers.HomeHandler()

}
```

---

# Pourquoi avons-nous changé le nom ?

Avant :

```go
package main

func homeHandler(...) {

}
```

Le handler était utilisé directement dans le même package.

Aucune exportation n'était nécessaire.

Maintenant :

```text
cmd/server
```

et

```text
internal/handlers
```

sont deux packages différents.

Le package `main` doit donc pouvoir accéder à la fonction.

Nous écrivons donc :

```go
func HomeHandler(...)
```

---

# La règle vaut pour tous les identifiants

Cette convention ne concerne pas uniquement les fonctions.

Elle s'applique aussi aux :

- structures (struct)
- méthodes
- variables
- constantes
- interfaces
- types

Exemple :

```go
type Club struct {
    Name string
}
```

La structure `Club` est exportée.

Le champ `Name` est également exporté.

En revanche :

```go
type club struct {
    name string
}
```

La structure `club` et le champ `name` ne sont visibles qu'à l'intérieur de leur package.

---

# Pourquoi cette convention ?

Go privilégie la simplicité.

Une seule règle suffit :

Majuscule = exporté

Minuscule = non exporté

Il n'est pas nécessaire d'ajouter des mots-clés supplémentaires.

---

# À retenir

- Une majuscule rend un identifiant exporté.
- Une minuscule le limite à son package.
- Cette règle s'applique aux fonctions, méthodes, structures, interfaces, variables, constantes et types.
- Une fonction exportée peut être utilisée par les autres packages du projet.
