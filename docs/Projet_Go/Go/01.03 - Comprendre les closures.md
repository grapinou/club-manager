---

## Objectif

Comprendre ce qu’est une **closure** en Go, pourquoi une fonction peut conserver l’accès à une variable extérieure et comment ce mécanisme est utilisé dans Club Manager.

Le mot français utilisé est parfois :

```text
fermeture
```

Mais le terme anglais **closure** est très courant en programmation.

---

# Définition simple

Une closure est une fonction qui utilise une variable déclarée en dehors d’elle et qui conserve l’accès à cette variable.

Exemple :

```go
func main() {
	message := "Bonjour"

	sayHello := func() {
		fmt.Println(message)
	}

	sayHello()
}
```

Résultat :

```text
Bonjour
```

La fonction anonyme :

```go
func() {
	fmt.Println(message)
}
```

utilise la variable extérieure :

```go
message
```

Cette fonction forme donc une closure.

---

# Fonction anonyme

Une fonction anonyme est une fonction qui ne possède pas de nom.

```go
func() {
	fmt.Println("Bonjour")
}
```

Elle peut être stockée dans une variable :

```go
sayHello := func() {
	fmt.Println("Bonjour")
}
```

Puis appelée avec :

```go
sayHello()
```

Une fonction anonyme n’est pas forcément une closure.

Elle devient une closure lorsqu’elle utilise une variable de son environnement extérieur.

---

## Fonction anonyme sans closure

```go
sayHello := func() {
	fmt.Println("Bonjour")
}
```

Cette fonction n’utilise aucune variable extérieure.

Elle est anonyme, mais ce n’est pas réellement une closure.

---

## Fonction anonyme avec closure

```go
message := "Bonjour"

sayHello := func() {
	fmt.Println(message)
}
```

La fonction utilise `message`, qui est déclarée à l’extérieur.

Elle forme donc une closure.

---

# La fonction capture une variable

On dit souvent que la fonction **capture** la variable extérieure.

```go
message := "Bonjour"

sayHello := func() {
	fmt.Println(message)
}
```

La fonction capture :

```go
message
```

La relation peut être représentée ainsi :

```text
message
   ↓
fonction anonyme
   ↓
la fonction conserve l’accès à message
```

---

# Exemple avec un compteur

```go
func main() {
	count := 0

	increment := func() {
		count++
		fmt.Println(count)
	}

	increment()
	increment()
	increment()
}
```

Résultat :

```text
1
2
3
```

La fonction `increment` conserve l’accès à :

```go
count
```

Elle ne reçoit pourtant aucun argument :

```go
increment()
```

La variable est accessible grâce à la closure.

---

# La closure peut modifier la variable

Une closure ne conserve pas seulement la valeur initiale.

Elle peut accéder à la variable elle-même.

```go
count := 0

increment := func() {
	count++
}
```

Chaque appel modifie la même variable :

```go
increment()
increment()
increment()

fmt.Println(count)
```

Résultat :

```text
3
```

La closure ne travaille donc pas nécessairement sur une copie indépendante.

---

# Retourner une fonction

Une fonction Go peut retourner une autre fonction.

Exemple :

```go
func NewGreeter(name string) func() {
	return func() {
		fmt.Println("Bonjour", name)
	}
}
```

Utilisation :

```go
func main() {
	greet := NewGreeter("Alice")

	greet()
}
```

Résultat :

```text
Bonjour Alice
```

La fonction extérieure reçoit :

```go
name
```

Puis elle retourne une fonction anonyme :

```go
return func() {
	fmt.Println("Bonjour", name)
}
```

La fonction retournée conserve l’accès à `name`.

---

# Même après la fin de la fonction extérieure

Lors de cet appel :

```go
greet := NewGreeter("Alice")
```

la fonction `NewGreeter` termine son exécution.

Pourtant, la fonction stockée dans `greet` peut encore utiliser :

```go
name
```

```go
greet()
```

La variable reste disponible parce qu’elle est utilisée par la closure.

```text
NewGreeter("Alice")
        ↓
création d’une fonction interne
        ↓
la fonction capture name
        ↓
NewGreeter se termine
        ↓
la fonction retournée utilise encore name
```

C’est l’un des points essentiels des closures.

---

# Plusieurs closures indépendantes

Chaque appel à la fonction extérieure peut créer un environnement différent.

```go
func NewGreeter(name string) func() {
	return func() {
		fmt.Println("Bonjour", name)
	}
}
```

Utilisation :

```go
aliceGreeter := NewGreeter("Alice")
bobGreeter := NewGreeter("Bob")

aliceGreeter()
bobGreeter()
```

Résultat :

```text
Bonjour Alice
Bonjour Bob
```

Chaque fonction retournée conserve son propre `name`.

```text
aliceGreeter → name = "Alice"
bobGreeter   → name = "Bob"
```

---

# Exemple de générateur de compteur

```go
func NewCounter() func() int {
	count := 0

	return func() int {
		count++
		return count
	}
}
```

Utilisation :

```go
counter := NewCounter()

fmt.Println(counter())
fmt.Println(counter())
fmt.Println(counter())
```

Résultat :

```text
1
2
3
```

Chaque appel utilise la même variable `count`.

---

## Deux compteurs différents

```go
counterA := NewCounter()
counterB := NewCounter()
```

Puis :

```go
fmt.Println(counterA())
fmt.Println(counterA())

fmt.Println(counterB())
```

Résultat :

```text
1
2
1
```

Chaque appel à `NewCounter` crée une nouvelle variable `count`.

```text
counterA → count propre
counterB → count propre
```

# Type d’une fonction

En Go, une fonction possède un type.

Par exemple :

```go
func()
```

désigne une fonction sans paramètre et sans valeur de retour.

```go
func() int
```

désigne une fonction sans paramètre qui retourne un entier.

```go
func(string) error
```

désigne une fonction qui reçoit une chaîne et retourne une erreur.

---

# `http.HandlerFunc`

Dans le package `net/http`, un handler possède cette signature :

```go
func(
	http.ResponseWriter,
	*http.Request,
)
```

Go définit le type suivant :

```go
type HandlerFunc func(
	ResponseWriter,
	*Request,
)
```

Une fonction qui possède cette signature peut donc être utilisée comme un `http.HandlerFunc`.

---

# Application à Club Manager

Avant l’utilisation de la configuration, le handler ressemblait à :

```go
func HomeHandler(
	w http.ResponseWriter,
	r *http.Request,
) {
	// traitement
}
```

Le routeur pouvait transmettre directement la fonction :

```go
mux.HandleFunc(
	"GET /{$}",
	handlers.HomeHandler,
)
```

Mais cette signature ne permet pas de transmettre `cfg`.

---

# Fonction extérieure et fonction intérieure

Nous avons transformé le handler ainsi :

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc {
	return func(
		w http.ResponseWriter,
		r *http.Request,
	) {
		// traitement
	}
}
```

Il y a maintenant deux fonctions.

## Fonction extérieure

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc
```

Elle reçoit la configuration.

## Fonction intérieure

```go
func(
	w http.ResponseWriter,
	r *http.Request,
)
```

Elle traite la requête HTTP.

La fonction intérieure utilise `cfg`, qui appartient à la fonction extérieure.

Elle forme donc une closure.

---

# Exemple complet

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc {
	return func(
		w http.ResponseWriter,
		r *http.Request,
	) {
		data := views.HomeData{
			Title:       cfg.SiteName,
			Heading:     "Bienvenue sur " + cfg.SiteName,
			Description: "Une application destinée à faciliter la gestion d'une association.",
		}

		err := views.RenderHome(w, data)
		if err != nil {
			http.Error(
				w,
				"Erreur interne du serveur",
				http.StatusInternalServerError,
			)
		}
	}
}
```

La fonction intérieure utilise :

```go
cfg.SiteName
```

alors que `cfg` est déclaré dans la fonction extérieure.

---

# Que se passe-t-il dans le routeur ?

Le routeur appelle :

```go
handlers.HomeHandler(cfg)
```

Cet appel ne traite pas encore une requête HTTP.

Il construit un handler.

```text
HomeHandler(cfg)
        ↓
création de la fonction interne
        ↓
la fonction capture cfg
        ↓
retour d’un http.HandlerFunc
```

Le routeur enregistre ensuite cette fonction :

```go
mux.HandleFunc(
	"GET /{$}",
	handlers.HomeHandler(cfg),
)
```

---

# Deux moments différents

Il faut distinguer deux moments.

## Au démarrage du serveur

```go
handlers.HomeHandler(cfg)
```

Cette expression crée le handler et lui associe la configuration.

## Lors d’une requête HTTP

```go
func(
	w http.ResponseWriter,
	r *http.Request,
)
```

La fonction interne est appelée par le routeur.

Elle peut toujours utiliser `cfg`.

---

# Représentation complète

```text
Démarrage de l’application
        ↓
config.Load()
        ↓
cfg
        ↓
router.New(cfg)
        ↓
HomeHandler(cfg)
        ↓
création d’une closure
        ↓
le routeur stocke le handler
        ↓
le serveur attend une requête
        ↓
GET /
        ↓
la closure est exécutée
        ↓
elle utilise cfg.SiteName
```

---

# Pourquoi utiliser une closure ici ?

La signature HTTP doit rester :

```go
func(
	http.ResponseWriter,
	*http.Request,
)
```

Nous ne pouvons pas imposer au routeur une signature comme :

```go
func(
	config.Config,
	http.ResponseWriter,
	*http.Request,
)
```

`http.HandleFunc` ne saurait pas appeler cette fonction.

La closure permet donc de fournir `cfg` à l’avance tout en retournant une fonction compatible avec le routeur.

```text
cfg fourni à la construction
        +
signature HTTP conservée
```

---

# Comparaison sans closure

On pourrait utiliser une variable globale :

```go
var cfg config.Config

func HomeHandler(
	w http.ResponseWriter,
	r *http.Request,
) {
	fmt.Fprintln(w, cfg.SiteName)
}
```

Mais cette approche rend la dépendance moins visible.

En lisant la signature :

```go
func HomeHandler(
	w http.ResponseWriter,
	r *http.Request,
)
```

on ne voit pas que la fonction dépend de `cfg`.

---

# Comparaison avec closure

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc
```

La dépendance est explicite.

```text
HomeHandler a besoin de Config
```

Le routeur doit la fournir :

```go
handlers.HomeHandler(cfg)
```

Cette forme est plus facile à comprendre et à tester.

---

# Closure et injection de dépendance

La closure n’est pas l’injection de dépendance elle-même.

Les deux notions sont liées, mais différentes.

## Injection de dépendance

```go
HomeHandler(cfg)
```

La configuration est fournie depuis l’extérieur.

## Closure

```go
return func(
	w http.ResponseWriter,
	r *http.Request,
) {
	fmt.Fprintln(w, cfg.SiteName)
}
```

La fonction retournée conserve l’accès à `cfg`.

```text
Injection de dépendance
└── cfg est transmis au handler

Closure
└── la fonction interne conserve cfg
```

cfg := config.Config{

# Closure par valeur ou variable capturée

Dans Club Manager, `cfg` est transmis par valeur :

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc
```

Chaque appel reçoit donc sa propre valeur de `Config`.

```go
homeHandler := HomeHandler(cfg)
clubHandler := ClubHandler(cfg)
```

Chaque closure conserve la configuration reçue lors de sa création.

---

# Attention aux modifications

Une closure peut observer les modifications d’une variable capturée.

```go
message := "Bonjour"

show := func() {
	fmt.Println(message)
}

message = "Bonsoir"

show()
```

Résultat :

```text
Bonsoir
```

La closure accède à la variable, et non nécessairement à sa valeur au moment de sa création.

---

# Exemple avec une boucle

Les closures dans les boucles peuvent demander de l’attention.

```go
functions := []func(){}

for i := 0; i < 3; i++ {
	functions = append(
		functions,
		func() {
			fmt.Println(i)
		},
	)
}
```

La compréhension exacte du comportement peut dépendre de la manière dont la variable de boucle est déclarée et de la version de Go utilisée.

La règle pédagogique à retenir est :

> lorsqu’une closure est créée dans une boucle, il faut vérifier quelle variable elle capture.

Une écriture explicite peut éviter l’ambiguïté :

```go
for i := 0; i < 3; i++ {
	value := i

	functions = append(
		functions,
		func() {
			fmt.Println(value)
		},
	)
}
```

Chaque closure capture alors une variable `value` distincte.

---

# Quand utiliser une closure ?

Une closure est utile lorsqu’une fonction doit conserver un contexte.

Exemples :

```text
configuration
logger
connexion à une base de données
service métier
paramètres
compteur
état local
fonction de validation
middleware HTTP
```

Dans une application web :

```go
func Handler(
	service Service,
) http.HandlerFunc
```

Dans un middleware :

```go
func LoggerMiddleware(
	next http.Handler,
) http.Handler
```

Dans une fonction de validation :

```go
func MinimumLength(
	length int,
) func(string) bool
```

---

# Exemple de validation

```go
func MinimumLength(
	length int,
) func(string) bool {
	return func(value string) bool {
		return len(value) >= length
	}
}
```

Utilisation :

```go
isLongEnough := MinimumLength(5)

fmt.Println(isLongEnough("Go"))
fmt.Println(isLongEnough("Golang"))
```

Résultat :

```text
false
true
```

La closure conserve la valeur :

```go
length = 5
```

---

# Exemple de middleware simplifié

```go
func AddHeader(
	name,
	value string,
	next http.Handler,
) http.Handler {
	return http.HandlerFunc(
		func(
			w http.ResponseWriter,
			r *http.Request,
		) {
			w.Header().Set(name, value)
			next.ServeHTTP(w, r)
		},
	)
}
```

La fonction interne conserve :

```text
name
value
next
```

Elle forme donc une closure.

---

# Avantages des closures

Les closures permettent de :

- conserver un contexte ;
    
- éviter certaines variables globales ;
    
- construire des fonctions configurées ;
    
- rendre les dépendances explicites ;
    
- respecter une signature imposée ;
    
- créer des fonctions réutilisables ;
    
- isoler un petit état local.
    

Dans Club Manager, elles permettent surtout de conserver :

```go
cfg
```

tout en respectant la signature imposée par `http.HandlerFunc`.

---

# Inconvénients et précautions

Les closures peuvent rendre le code plus difficile à comprendre lorsqu’elles :

- capturent beaucoup de variables ;
    
- modifient un état caché ;
    
- sont fortement imbriquées ;
    
- vivent longtemps ;
    
- sont créées dans des boucles sans précaution ;
    
- partagent des données modifiables entre plusieurs goroutines.
    

Pour rester lisible, une closure doit généralement capturer peu de valeurs et avoir un rôle clair.

# Comprendre et retenir

Une closure est une fonction qui conserve l’accès à une variable extérieure.

Exemple minimal :

```go
message := "Bonjour"

show := func() {
	fmt.Println(message)
}
```

La fonction `show` capture `message`.

Une fonction peut également retourner une closure :

```go
func NewGreeter(
	name string,
) func() {
	return func() {
		fmt.Println(name)
	}
}
```

Même après la fin de `NewGreeter`, la fonction retournée conserve l’accès à `name`.

Dans Club Manager :

```go
func HomeHandler(
	cfg config.Config,
) http.HandlerFunc {
	return func(
		w http.ResponseWriter,
		r *http.Request,
	) {
		fmt.Fprintln(w, cfg.SiteName)
	}
}
```

La fonction interne capture :

```go
cfg
```

Cela permet de combiner :

```text
une configuration fournie à l’avance
                +
la signature imposée par http.HandlerFunc
```

La phrase essentielle à retenir est :

> Une closure est une fonction qui se souvient de l’environnement dans lequel elle a été créée.

Dans notre projet :

```text
HomeHandler(cfg)
        ↓
retourne une fonction HTTP
        ↓
cette fonction se souvient de cfg
```
