# Utiliser les interfaces en Go

## Objectif

Une interface permet de travailler avec un comportement plutôt qu'avec un type précis.

On ne demande pas :

> "Quel est ton type ?"

On demande :

> "Qu'est-ce que tu sais faire ?"

---

# 1. Créer une interface

Une interface décrit un ensemble de méthodes.

Exemple :

```go
type Speaker interface {
	Speak()
}
```

Cette interface signifie :

> Tout objet qui possède une méthode `Speak()` est un Speaker.

---

# 2. Créer des structures qui respectent l'interface

## Structure Dog

```go
type Dog struct{}

func (d Dog) Speak() {
	fmt.Println("Wouf")
}
```

Remarque : 

- `Dog` est bien une struct vide

```go
type Dog struct{}
```

déclare une structure qui ne contient **aucun champ**.
Elle pourrait contenir des informations :

```go
type Dog struct {
	Name string
	Age  int
}
```

-  `Speak()` est bien une méthode de `Dog`

Cette partie :

```go
func (d Dog) Speak()
```

signifie :

> "Je crée une méthode appelée `Speak` qui appartient au type `Dog`."

Le `(d Dog)` est le **receiver** (récepteur).

On pourrait le comparer à `this` ou `self` dans d'autres langages.

Par exemple :

```go
type Dog struct {
	Name string
}

func (d Dog) Speak() {
	fmt.Println(d.Name, "fait Wouf")
}
```

Ici la méthode utilise les données du chien.

- Est-ce que `Speak()` fait partie de l'interface `Speaker` ?

Non, **la méthode `Speak()` n'appartient pas à l'interface**.

L'interface `Speaker` **déclare qu'elle exige une méthode `Speak()`** :

```
type Speaker interface {
	Speak()
}
```

Elle dit simplement :

> "Pour être considéré comme un Speaker, il faut avoir une méthode appelée `Speak()`."

Ensuite, `Dog` possède une méthode `Speak()` :

```
func (d Dog) Speak()
```

Donc Go constate :

```
Speaker demande :
    Speak()

Dog possède :
    Speak()

Donc :
    Dog satisfait Speaker
```

---

On pourrait représenter cela comme ceci :

```
Interface Speaker

+----------------+
| Speak()        |
+----------------+


        correspond


Struct Dog

+----------------+
| Speak()        |
+----------------+
```

La méthode n'est pas copiée dans l'interface.

Il y a simplement une **correspondance de signature**.

> **Comme la struct `Dog` possède une méthode `Speak`, `Dog` est aussi un `Speaker`.**

est correcte.

En Go, on dira encore plus précisément :

> **Le type `Dog` satisfait l'interface `Speaker`.**

ou

> **`Dog` implémente l'interface `Speaker`.**

Les deux formulations sont courantes, même si dans la documentation Go, le terme **"satisfait"** (_satisfies_) est privilégié.

> **Une interface est un contrat. Si un type respecte ce contrat, il satisfait automatiquement l'interface.**

Dans notre exemple :

- `Speaker` est le contrat.
- `Dog` respecte le contrat.
- Donc `Dog` est un `Speaker`.

C'est exactement la philosophie de Go : **on ne déclare pas qu'un type implémente une interface, on le constate parce que ses méthodes correspondent au contrat.** C'est ce qui rend les interfaces Go à la fois simples et très puissantes.
## Structure Cat

```go
type Cat struct{}

func (c Cat) Speak() {
	fmt.Println("Miaou")
}
```

Ni `Dog` ni `Cat` ne déclarent utiliser `Speaker`.

En Go, l'implémentation est automatique.

---

# 3. Utiliser une interface dans une fonction

On peut créer une fonction qui accepte n'importe quel Speaker.

```go
func MakeSpeak(s Speaker) {
	s.Speak()
}
```

La fonction ne connaît pas le type réel.

Elle sait seulement que l'objet possède :

```go
Speak()
```

---

# Exemple complet

```go
package main

import "fmt"

type Speaker interface {
	Speak()
}

type Dog struct{}

func (d Dog) Speak() {
	fmt.Println("Wouf")
}

type Cat struct{}

func (c Cat) Speak() {
	fmt.Println("Miaou")
}

func MakeSpeak(s Speaker) {
	s.Speak()
}

func main() {

	dog := Dog{}
	cat := Cat{}

	MakeSpeak(dog)
	MakeSpeak(cat)
}
```

Résultat :

```
Wouf
Miaou
```

---

# 4. Stocker une interface dans une variable

Une interface peut contenir un objet concret.

Exemple :

```go
var animal Speaker

animal = Dog{}

animal.Speak()
```

Ici :

```
animal
 |
 └── Dog
```

La variable connaît seulement l'interface.

Elle ignore le type réel.

---

# 5. Pourquoi utiliser une interface ?

Sans interface :

```go
func MakeSpeak(d Dog)
```

Cette fonction accepte uniquement un chien.

Avec une interface :

```go
func MakeSpeak(s Speaker)
```

Elle accepte :

- un chien ;
- un chat ;
- tout objet capable de parler.

---

# Les interfaces composées

Une interface peut utiliser d'autres interfaces.

On appelle cela la composition.

---

# Exemple simple

Première interface :

```go
type Reader interface {
	Read()
}
```

Deuxième interface :

```go
type Writer interface {
	Write()
}
```

On peut créer :

```go
type ReadWriter interface {
	Reader
	Writer
}
```

Maintenant :

```go
ReadWriter
```

oblige à posséder :

```go
Read()
Write()
```

---

# Représentation

```
        Reader
           |
           |
      ReadWriter
           |
           |
        Writer
```

Ou :

```
ReadWriter = Reader + Writer
```

---

# Exemple concret

```go
type Reader interface {
	Read()
}

type Writer interface {
	Write()
}

type ReadWriter interface {
	Reader
	Writer
}


type File struct{}

func (f File) Read() {
	fmt.Println("Lecture")
}

func (f File) Write() {
	fmt.Println("Écriture")
}
```

`File` possède :

```go
Read()
Write()
```

Donc il respecte :

```go
ReadWriter
```

---

# Utilisation

```go
func ProcessFile(rw ReadWriter) {

	rw.Read()
	rw.Write()

}
```

Puis :

```go
file := File{}

ProcessFile(file)
```

Résultat :

```
Lecture
Écriture
```

# Les bonnes pratiques Go

## Préférer les petites interfaces

Éviter :

```go
type Machine interface {
	Print()
	Scan()
	Fax()
	Copy()
}
```

Car peu d'objets auront besoin de tout.

---

Préférer :

```go
type Printer interface {
	Print()
}

type Scanner interface {
	Scan()
}
```

Puis composer si nécessaire :

```go
type MultiFunction interface {
	Printer
	Scanner
}
```

# Interfaces dans Club Manager

Nous utiliserons probablement ce principe :

```
Handler
   |
   ▼
Service
   |
   ▼
Repository (interface)
   |
   ▼
PostgreSQL
```

Exemple futur :

```go
type MemberRepository interface {
	FindMember(id int)
	CreateMember()
}
```

Le service ne saura pas si les données viennent :

- de PostgreSQL ;
- d'un fichier ;
- d'une base de test.

Il connaîtra seulement les capacités disponibles.

---

# À retenir

Une interface :

- décrit des comportements ;
- ne contient pas de données ;
- est satisfaite automatiquement en Go ;
- permet le polymorphisme sans héritage ;
- peut être composée d'autres interfaces.

Principe clé :

> Une interface Go décrit ce qu'un objet sait faire, pas ce qu'il est.
