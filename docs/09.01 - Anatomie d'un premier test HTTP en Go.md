MOC : [[09 - TESTS]]

---

## Objectif

Nous voulons tester le handler de la page d'accueil :

```go
func HomeHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Accueil")
}
```

Un handler HTTP reçoit deux éléments :

```go
http.ResponseWriter
*http.Request
```

Pour tester ce handler, nous devons donc lui fournir :

- une requête HTTP simulée ;
    
- un objet capable d'enregistrer la réponse.
    

La bibliothèque standard de Go fournit le package :

```go
net/http/httptest
```

Ce package permet de tester du code HTTP sans lancer réellement un serveur.

---

## Exemple complet

```go
package handlers

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestHomeHandler(t *testing.T) {
	request := httptest.NewRequest(http.MethodGet, "/", nil)
	response := httptest.NewRecorder()

	HomeHandler(response, request)
}
```

Ce premier exemple exécute le handler, mais ne vérifie pas encore son résultat.

Il permet néanmoins de comprendre les quatre éléments essentiels :

```go
func TestHomeHandler(t *testing.T)
request := httptest.NewRequest(http.MethodGet, "/", nil)
response := httptest.NewRecorder()
HomeHandler(response, request)
```

# 1. La fonction de test

```go
func TestHomeHandler(t *testing.T)
```

## `func`

Le mot-clé `func` permet de déclarer une fonction en Go.

```go
func nomDeLaFonction() {
}
```

Notre fonction de test est donc une fonction Go classique, avec quelques conventions particulières.

---

## `TestHomeHandler`

```go
TestHomeHandler
```

Le nom d'une fonction de test doit commencer par :

```text
Test
```

La partie suivante décrit généralement ce que nous voulons tester :

```text
Test + HomeHandler
```

Ce qui donne :

```go
TestHomeHandler
```

La commande `go test` recherche automatiquement les fonctions qui respectent cette forme.

Exemples :

```go
func TestHomeHandler(t *testing.T)
func TestClubHandler(t *testing.T)
func TestContactHandler(t *testing.T)
func TestUnknownRoute(t *testing.T)
```

Le nom doit être explicite.

Il doit permettre de comprendre rapidement le comportement vérifié.

---

## `t *testing.T`

```go
t *testing.T
```

Le paramètre `t` est fourni automatiquement par le système de test de Go.

Son type est :

```go
*testing.T
```

`testing.T` représente le test en cours.

Le pointeur `*testing.T` permet d'utiliser cet objet pour :

- signaler une erreur ;
    
- arrêter le test ;
    
- écrire des informations ;
    
- créer des sous-tests ;
    
- marquer des fonctions auxiliaires.
    

Exemples :

```go
t.Error("une erreur est survenue")
```

```go
t.Errorf("statut obtenu : %d", status)
```

```go
t.Fatal("le test ne peut pas continuer")
```

```go
t.Fatalf("statut obtenu : %d", status)
```

Différence générale :

```text
Error / Errorf  → signale l'échec mais continue le test
Fatal / Fatalf  → signale l'échec et arrête immédiatement le test
```

Dans notre premier exemple, `t` n'est pas encore utilisé.

Il le sera lorsque nous comparerons le résultat obtenu avec le résultat attendu.

---

## Structure d'une fonction de test

Une fonction de test Go possède donc la structure suivante :

```go
func TestNomDuComportement(t *testing.T) {
	// préparation

	// exécution

	// vérification
}
```

Ces trois étapes sont souvent résumées ainsi :

```text
Arrange → Act → Assert
```

En français :

```text
Préparer → Exécuter → Vérifier
```

# 2. Créer une requête simulée

```go
request := httptest.NewRequest(http.MethodGet, "/", nil)
```

Cette instruction crée une requête HTTP utilisable dans un test.

Elle ne contacte aucun serveur.

Elle construit simplement un objet de type :

```go
*http.Request
```

Cet objet ressemble à la requête que le handler recevrait dans l'application réelle.

---

## `request :=`

```go
request :=
```

`request` est le nom de la variable.

L'opérateur `:=` permet de déclarer et d'initialiser une variable.

```go
request := valeur
```

Go déduit automatiquement le type de la variable.

Ici, le type de `request` sera :

```go
*http.Request
```

Nous pourrions écrire de manière plus explicite :

```go
var request *http.Request
request = httptest.NewRequest(http.MethodGet, "/", nil)
```

Mais la forme courte est plus naturelle :

```go
request := httptest.NewRequest(http.MethodGet, "/", nil)
```

---

## `httptest.NewRequest`

```go
httptest.NewRequest(...)
```

`httptest` est le package importé :

```go
import "net/http/httptest"
```

`NewRequest` est une fonction fournie par ce package.

Elle permet de construire une requête HTTP spécialement adaptée aux tests.

Sa forme simplifiée est :

```go
httptest.NewRequest(method, target, body)
```

Elle reçoit donc trois arguments :

```text
méthode HTTP
adresse demandée
corps de la requête
```

---

## Premier argument : `http.MethodGet`

```go
http.MethodGet
```

Cet argument indique la méthode HTTP utilisée.

Ici, nous simulons une requête :

```http
GET /
```

Go fournit des constantes pour les méthodes HTTP courantes :

```go
http.MethodGet
http.MethodPost
http.MethodPut
http.MethodPatch
http.MethodDelete
```

Nous pourrions techniquement écrire :

```go
"GET"
```

Mais il est préférable d'utiliser :

```go
http.MethodGet
```

Cela évite les fautes de frappe et rend l'intention plus claire.

---

## Deuxième argument : `"/"`

```go
"/"
```

Cet argument représente la cible de la requête.

Ici, nous voulons tester la page d'accueil :

```text
/
```

Pour tester la page de contact, nous pourrions utiliser :

```go
"/contact"
```

Pour la page du club :

```go
"/club"
```

Pour une page inconnue :

```go
"/page-inconnue"
```

Dans un test de handler isolé, le chemin n'a pas toujours d'influence directe sur la réponse.

Il est cependant important de créer une requête cohérente avec le comportement testé.

---

## Troisième argument : `nil`

```go
nil
```

Le troisième argument représente le corps de la requête HTTP.

Une requête `GET` vers la page d'accueil n'a pas besoin de transmettre de données.

Nous utilisons donc :

```go
nil
```

`nil` signifie ici qu'aucun corps de requête n'est fourni.

Pour une requête envoyant des données, nous pourrions utiliser un lecteur.

Exemple futur :

```go
body := strings.NewReader("name=Rémi")
request := httptest.NewRequest(http.MethodPost, "/contact", body)
```

Pour notre page d'accueil :

```go
httptest.NewRequest(http.MethodGet, "/", nil)
```

est suffisant.

---

## Résultat obtenu

Après cette instruction :

```go
request := httptest.NewRequest(http.MethodGet, "/", nil)
```

nous avons en mémoire une requête représentant approximativement :

```http
GET / HTTP/1.1
```

Cette requête pourra être transmise à notre handler.

---

# 3. Créer un enregistreur de réponse

```go
response := httptest.NewRecorder()
```

Dans une véritable application, le serveur fournit au handler un :

```go
http.ResponseWriter
```

Le handler écrit sa réponse dans cet objet :

```go
fmt.Fprintln(w, "Accueil")
```

Dans un test, aucun véritable serveur n'est lancé.

Nous avons donc besoin d'un faux `ResponseWriter` capable d'enregistrer ce que le handler écrit.

C'est le rôle de :

```go
httptest.NewRecorder()
```

---

## `response :=`

```go
response :=
```

Nous créons une variable appelée `response`.

Son type est déduit automatiquement par Go.

Le type concret retourné est :

```go
*httptest.ResponseRecorder
```

---

## `httptest.NewRecorder()`

```go
httptest.NewRecorder()
```

`NewRecorder` crée un enregistreur de réponse HTTP.

Cet objet peut recevoir ce que le handler écrit et le conserver afin que nous puissions ensuite l'examiner.

Il enregistre notamment :

- le statut HTTP ;
    
- les en-têtes HTTP ;
    
- le contenu de la réponse.
    

Exemples de valeurs accessibles :

```go
response.Code
```

```go
response.Header()
```

```go
response.Body.String()
```

---

## Pourquoi un recorder ?

Dans l'application réelle :

```text
Handler
   ↓
ResponseWriter fourni par le serveur
   ↓
Réponse envoyée au navigateur
```

Dans le test :

```text
Handler
   ↓
ResponseRecorder
   ↓
Réponse conservée en mémoire
   ↓
Vérifications
```

Le `ResponseRecorder` remplace donc temporairement le véritable mécanisme de réponse du serveur.

---

## Compatibilité avec `http.ResponseWriter`

Notre handler attend :

```go
func HomeHandler(w http.ResponseWriter, r *http.Request)
```

Mais `httptest.NewRecorder()` retourne :

```go
*httptest.ResponseRecorder
```

Cela fonctionne parce que `ResponseRecorder` possède les méthodes nécessaires pour satisfaire l'interface :

```go
http.ResponseWriter
```

C'est un exemple concret d'utilisation d'une interface.

Le handler ne demande pas un type précis.

Il demande simplement un objet capable de se comporter comme un `http.ResponseWriter`.

```text
ResponseRecorder possède les méthodes requises
                ↓
ResponseRecorder est un ResponseWriter
                ↓
Il peut être transmis au handler
```

---

# 4. Exécuter le handler

```go
HomeHandler(response, request)
```

Cette instruction appelle directement le handler.

La signature de `HomeHandler` est :

```go
func HomeHandler(w http.ResponseWriter, r *http.Request)
```

Il attend donc deux arguments, dans cet ordre :

```text
1. un http.ResponseWriter
2. un *http.Request
```

Nous lui transmettons :

```text
response → enregistreur de réponse
request  → requête simulée
```

Ce qui donne :

```go
HomeHandler(response, request)
```

---

## Ce qui se passe pendant l'appel

Supposons que le handler soit :

```go
func HomeHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Accueil")
}
```

Lors du test :

```go
HomeHandler(response, request)
```

le déroulement est le suivant :

```text
request représente GET /
        ↓
HomeHandler est exécuté
        ↓
fmt.Fprintln écrit "Accueil"
        ↓
response enregistre le texte
```

Après l'appel, nous pouvons récupérer le contenu avec :

```go
response.Body.String()
```

---

## Aucun serveur n'est lancé

L'instruction :

```go
HomeHandler(response, request)
```

appelle directement une fonction Go.

Elle ne lance pas :

```go
http.ListenAndServe
```

Elle n'utilise pas :

- le port `8080` ;
    
- le navigateur ;
    
- le réseau ;
    
- le routeur.
    

Nous testons uniquement le handler.

C'est ce que l'on appelle ici un test isolé du handler.

Le test peut être représenté ainsi :

```text
httptest.NewRequest
        ↓

        ↓
HomeHandler
        ↓
http.ResponseWriter
        ↓
ResponseRecorder
        ↓
Réponse enregistrée
```

Ou avec les noms de nos variables :

```text
request
   ↓
HomeHandler(response, request)
   ↓
response
```

# Ajouter une première vérification

Pour que le test soit réellement utile, nous devons vérifier le résultat.

Par exemple :

```go
func TestHomeHandler(t *testing.T) {
	request := httptest.NewRequest(http.MethodGet, "/", nil)
	response := httptest.NewRecorder()

	HomeHandler(response, request)

	if response.Code != http.StatusOK {
		t.Errorf(
			"statut obtenu : %d, statut attendu : %d",
			response.Code,
			http.StatusOK,
		)
	}
}
```

---

## `response.Code`

```go
response.Code
```

Cette valeur correspond au statut HTTP enregistré.

Exemples de statuts :

```text
200 → OK
404 → Not Found
500 → Internal Server Error
```

---

## `http.StatusOK`

```go
http.StatusOK
```

Cette constante représente le statut :

```text
200
```

Il est préférable d'écrire :

```go
http.StatusOK
```

plutôt que :

```go
200
```

La constante rend le code plus lisible.

---

## La comparaison

```go
if response.Code != http.StatusOK
```

Cette condition signifie :

```text
si le statut obtenu est différent du statut attendu
```

Alors le test signale une erreur :

```go
t.Errorf(...)
```

---

# Vérifier le contenu de la page

Nous pouvons également examiner le contenu enregistré :

```go
body := response.Body.String()
```

Puis le comparer :

```go
if body != "Accueil\n" {
	t.Errorf(
		"contenu obtenu : %q, contenu attendu : %q",
		body,
		"Accueil\n",
	)
}
```

Le caractère :

```text
\n
```

représente un retour à la ligne.

Il est présent parce que :

```go
fmt.Fprintln
```

ajoute automatiquement un retour à la ligne après le texte.

---

## Test complet

```go
func TestHomeHandler(t *testing.T) {
	request := httptest.NewRequest(http.MethodGet, "/", nil)
	response := httptest.NewRecorder()

	HomeHandler(response, request)

	if response.Code != http.StatusOK {
		t.Errorf(
			"statut obtenu : %d, statut attendu : %d",
			response.Code,
			http.StatusOK,
		)
	}

	body := response.Body.String()

	if body != "Accueil\n" {
		t.Errorf(
			"contenu obtenu : %q, contenu attendu : %q",
			body,
			"Accueil\n",
		)
	}
}
```

Le texte attendu doit être adapté au contenu réel de `HomeHandler`.

# Préparer, exécuter, vérifier

Notre test complet respecte trois étapes.

## 1. Préparer

```go
request := httptest.NewRequest(http.MethodGet, "/", nil)
response := httptest.NewRecorder()
```

Nous préparons :

- la requête ;
    
- l'enregistreur de réponse.
    

## 2. Exécuter

```go
HomeHandler(response, request)
```

Nous exécutons le code à tester.

## 3. Vérifier

```go
if response.Code != http.StatusOK {
	t.Errorf(...)
}
```

```go
if response.Body.String() != "Accueil\n" {
	t.Errorf(...)
}
```

Nous comparons le résultat obtenu avec le résultat attendu.

# Comprendre et retenir

Une fonction de test Go commence par `Test` et reçoit un paramètre :

```go
func TestHomeHandler(t *testing.T)
```

`testing.T` représente le test en cours et permet de signaler les erreurs.

Une requête HTTP simulée est créée avec :

```go
request := httptest.NewRequest(http.MethodGet, "/", nil)
```

Les trois arguments représentent :

```text
méthode HTTP
chemin demandé
corps de la requête
```

Un enregistreur de réponse est créé avec :

```go
response := httptest.NewRecorder()
```

Il remplace le véritable `http.ResponseWriter` et conserve la réponse en mémoire.

Le handler est ensuite exécuté directement :

```go
HomeHandler(response, request)
```

La logique générale est :

```text
Préparer
   ↓
Exécuter
   ↓
Vérifier
```

Dans notre exemple :

```text
Créer une requête
Créer un enregistreur
Appeler HomeHandler
Examiner la réponse
```

Le test du handler n'a besoin :

- ni d'un serveur lancé ;
    
- ni d'un port ;
    
- ni d'un navigateur ;
    
- ni d'une connexion réseau.
